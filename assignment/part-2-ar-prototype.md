# Part 2｜MIMIC 表情气象台：从“能跑”到可验证的交互

版本：v0.2，2026-10-15。基于用户对v0.1的真实反馈，经过三个独立Agent审阅及三轮修改、测试和复核。

## 一、交付入口与体验方法

- **Live Demo：** https://xieyuh03.github.io/mimic-ar-playground/
- **Public源码及全部资料：** https://github.com/xieyuh03/mimic-ar-playground
- **持续集成与发布：** https://github.com/xieyuh03/mimic-ar-playground/actions/workflows/deploy.yml
- **换电脑接续：** 仓库根目录的 `CONTINUE.md`；三部分可编辑文档、原图及校验和均位于 `assignment/`。

使用Node.js 22.12+，克隆仓库后执行 `npm ci`、`npm run dev`。生成生产包使用 `npm run build`；无需后端API Key或原电脑的本地路径。

### 现场体验

1. 在HTTPS页面点击“开启摄像头”，单人入镜。保持自然表情约2秒，建立个人基线。
2. 微笑会下雨；保持笑容并自然张嘴片刻，大笑优先切换烟花，旧雨立即移除。
3. 大笑仍难触发时，点击“学习我的大笑”，保持表情约1.5秒。也可适度提高灵敏度；说话误触则调低。
4. 查看“大笑准备”、张嘴系数、嘴部开度及等待原因，区别“还在收集证据”与“已经进入大笑状态”。
5. 左右移动头部，观察粒子与轮廓接触后的反弹；可以显示碰撞体或放大画面。
6. 停止摄像头后释放媒体轨道。手动特效演示始终明确标注“非摄像头”，不当作识别结果。

## 二、用户反馈如何转化成可复现问题

v0.1的问题不只是视觉弱：分类器要求高微笑、高张嘴与足够脸颊信号同时出现，部分开放笑容组合过不了门；而渲染器只停止新雨滴，旧雨还能持续数秒，进一步制造“烟花和微笑冲突”的观感。

我们没有用户原始面部数据，不能声称完全还原了其某次表情。以下为**可以解释反馈、且能在原实现稳定复现的合成轨迹**：

| 持续2.4秒的输入（smile / jaw / cheek） | v0.1 | v0.2 |
|---|---|---|
| 0.48 / 0.38 / 0.025 | smile，0次烟花请求 | laugh，2次请求 |
| 0.68 / 0.31 / 0.03 | smile，0次请求 | laugh，2次请求 |
| 0.78 / 0.06 / 0.20，闭嘴微笑 | smile，0次 | 保持smile，0次 |
| 0.08 / 0.85 / 0.02，仅张嘴 | neutral，0次 | 保持neutral，0次 |

这张表证明同一输入下的程序行为修复，**不是4名用户、不是准确率、也不是模型识别能力的统计评估**。

### 2.1 识别修正

- 脸颊动作改为辅助信息，不再硬否决大笑。
- Worker从实际landmarks计算内唇开度/嘴宽、嘴宽/脸宽；先转换到视频像素坐标，再投影到嘴角连线的垂直方向，避免横竖画幅和歪头造成比例错误。
- 联合当前笑容、最多900ms的近期笑容、嘴部几何或jaw信号；保留当前笑容下限，避免“刚笑过就打哈欠”被判大笑。
- 使用520ms证据确认窗口，容忍短抖动；短说话式开闭脉冲不能仅靠平滑尾巴累积成大笑。
- 确认后最少展示650ms，保证0.42秒升空过程有机会完成；展示保留不产生新的识别证据或新发射请求。丢脸、旧帧和手动停止立即取消。
- 跟踪重置与会话重置分开：短暂丢脸不重置1.2秒冷却。
- 自然基线采样要求真实持续时间和最低样本量；丢脸、长间隔、遮挡或页面隐藏打断采样。
- 增加经过有效性检查的个人大笑参考与有界灵敏度。参考仅保存在当前内存，不记录照片或持久化生物特征。

### 2.2 视觉修正

雨幕采用三层速度、宽度、透明度及长度，进入时在整个画面预布置雨滴，而不是等雨从画顶落满。风向一致，近层更清楚，画面底部出现短时水花；亮背景有暗底与细描边，不靠无上限粒子数。

烟花采用“上升尾焰→错峰爆炸→重力下坠→曲线拖尾与渐隐”。粒子使用球面方向的2D投影而非固定内外圆环，每发使用连贯色系；四点轨迹在碰撞后重置，避免穿过头部的拖尾。接触反馈只在有明显冲量时出现，计入统一粒子预算。

雨幕与烟花互斥：切换时移除不兼容粒子与队列。退出烟花不仅取消待发槽，还删除在途火箭，禁止在无人脸或中性状态下继续产生新爆炸。

## 三、工程架构与成本边界

```text
用户授权摄像头成功
  → 本站固定版本模型 + 同版本WASM + 经典Worker
  → 480px视频帧（最多1帧在途，无积压）
  → 实际blendshape + 像素比例正确的嘴部几何 + 头部锚点
  → 个人基线/大笑参考 + 时序证据与互斥状态
  → Canvas有界粒子池 + 固定步长 + 移动椭圆扫掠碰撞
```

| 项目 | 本版约束 |
|---|---|
| 模型与运行时 | MediaPipe Tasks Vision 0.10.32；SDK与WASM同版本；人脸模型SHA-256固定验证 |
| 模型加载 | 仅在摄像头授权成功并能播放后加载；拒权/只浏览/只手动演示时，模型相关请求为0 |
| 推理频率 | 正常最高约12.5Hz、节能约6.7Hz；还受上次推理耗时的1.5倍限制 |
| 在途帧 | 捕获与推理合计最多1帧；过时机会直接跳过，不排队存视频 |
| 粒子上限 | 正常720、节能360、低动态180；尾焰、水花和碰撞光斑都计入 |
| 发射队列 | 最多6个定长槽；正常一组最多3发，节能/低动态一发 |
| Canvas | DPR≤1.75；节能≤1；总backing pixels约250万硬上限 |
| 数值内存 | 粒子、4点轨迹和发射队列全部类型化数组总计低于64KiB；光晕小图集只建一次 |
| 物理更新 | 固定1/120秒；一次绘制最多补4步，O(N)，没有粒子间两两碰撞 |
| 冷却与暂停 | 常规至少1.2秒，低动态至少2.4秒；后台暂停，返回不追赶无限旧帧 |
| 失效处理 | 400ms旧关键点作废；单帧4秒未完成停机报错；模型加载超时、取消、旧会话回调均显式处理 |

### 成本不能只看主包

本版本地构建业务JS约36.8KB，gzip估计约14.4KB；复杂度增加但仍远小于模型和WASM：

- 固定模型：3,758,596 bytes。
- SIMD WASM：11,453,626 bytes，加约205KB加载器和独立Worker。
- 原始冷启动资源约15.6MB；静态部署包含SIMD与非SIMD两套，但客户端只使用合适的一套。
- v0.1线上冷启动曾实测6,844,299 bytes传输、15,596,127 bytes解码后体积。该历史数字不冒充v0.2新增业务包的精确网络成绩。

ROI策略是“授权后才加载、浏览器缓存、一个在途帧、低端自动降级、无服务器推理账单”，不是“终端算力与电量免费”。原图及报告属于仓库资料，不会被应用页面自动下载。

## 四、三轮验证与已知边界

### 4.1 自动化证据

最终代码的本地验证：

- **112项单元测试通过**：其中71项表情时序与校准相关核心测试；另覆盖嘴部几何、采样中断、镜像裁切、碰撞、资源上限及渐隐数据。
- **21项浏览器测试通过**：包含低cheek/低jaw回归、真实主界面天气切换、短大笑展示、说话/哈欠负例、个人参考、页面隐藏、加载取消、拒权零下载、真实WASM模型、多人/无脸及终端alpha。
- **JSON Schema严格验证**：Ajv Draft 2020-12接受3个合法分支，拒绝11个无效/互相矛盾指令；20行评分算式和200字复盘同时检查。

浏览器测试中的合成系数fixture只替换推理输出，仍走实际摄像头模式的校准、状态机与渲染，**不是只点击“体验烟花”来代替识别验收**。另一项真实WASM模型测试使用授权图片03生成的本地Canvas视频流，验证几何提取、单人校准、多人暂停和无人脸清理；它不是动态真人表情数据集。

### 4.2 可见性：测量目标而非只截图

固定随机种子，在桌面1440px与移动390px视口检查雨幕/烟花。测量排除虚拟头像和均匀暗底，再计算源像素合成到亮底232/暗底24后的亮度差：

| 样本 | 雨幕有效像素占比 | 亮底对比覆盖 | 烟花有效像素占比 | 亮底对比覆盖 |
|---|---:|---:|---:|---:|
| 桌面视口 | 2.71% | 2.06% | 7.00% | 3.99% |
| 手机视口模拟 | 2.88% | 1.97% | 12.76% | 7.28% |

实际阈值为雨幕亮/暗对比覆盖>0.8%，烟花亮底>0.8%、暗底>1%；雨幕横向覆盖>85%、纵向>75%。这些证明“效果占据可观察面积、没有被亮底完全吃掉”，不证明语义写实度。截图附在PDF与仓库证据中，渲染相位随真实帧调度略有变化。

独立Canvas测试还验证：单粒子及拖尾的末端alpha积分小于中段3%，避免只检查 `life` 字段而没有真正淡出。

### 4.3 性能采样

每个场景连续30秒，桌面Chromium141无头运行，正常前台帧率约60FPS。设备为本次执行环境，不是产品承诺的最低端手机。

| 场景 | 输入与范围 | 主要结论 |
|---|---|---|
| 桌面持续烟花 | 1440×1100，系统DPR2、Canvas上限1.75 | 已测约60FPS；p95帧间隔约16.8ms；最大采样滚动CPU p95约0.8ms；峰值713粒子 |
| 移动视口雨幕 | 390×844、DPR2的桌面模拟 | 约60FPS；未突破粒子与像素预算；不是手机温升/电量成绩 |
| 实际模型＋无脸模拟采集设备 | 1440×1100、DPR1 | 主线程继续稳定渲染、最多1帧在途；不是有人脸时最坏推理延迟 |

原始结果由 `npm run test:performance` 生成，公开摘要保留在 `assignment/evidence/performance-v2.json`。验收预算：主线程采样滚动p95≤8ms，p95帧间隔≤33.5ms、粒子≤720、在途帧≤1、Canvas约250万像素。这里的“最大采样滚动p95”**不是把全程所有帧重新合并计算的p95**。

### 4.4 尚未完成，不能混淆

1. 新版仍需用户实际试用，收集不同人脸、说话、微笑、大笑、遮挡和弱光的失败场景。
2. 持续带笑说话可能与张嘴大笑在视觉上不可分；没有音频就不能承诺真实笑声识别。
3. iOS Safari、Android Chrome真机的5分钟帧率、温升、续航、旋转与后台恢复仍待验证。
4. 头部碰撞为2D椭圆，不是3D头模，没有真实前后遮挡或头发轮廓。
5. 新版目标可设为约定数据集触发精确率≥90%、确认后的视觉响应≤1秒、基线设备p95帧间隔≤33.5ms；这些目标中未实测的部分不能写成“已达标”。

建议下一轮：在至少两类手机上，以明确标注的自然中性、微笑、大笑、说话、打哈欠样本各20段以上，报告混淆矩阵和分条件结果。先核对个人参考与几何诊断，再决定是否调整全局阈值。

## 五、Vibecoding 复盘（200 字以内）

最大陷阱是用理想高系数样本验证识别：脸颊硬门槛让开放笑容仍下雨，旧雨滴又制造冲突。改为嘴部几何与时序证据、互斥天气，并补低系数、说话、丢脸回归。纠偏Prompt：“不要只调阈值；复现失败轨迹，验证大笑优先、旧雨为零及亮背景可见，保留误触负例。”
